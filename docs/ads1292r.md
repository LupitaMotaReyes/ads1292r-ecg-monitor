# ADS1292R

The ADS1292R is a Texas Instruments dual-channel, 24-bit analog front-end for ECG
and respiration acquisition. The device this project targets is mounted on a
purple CWXS module and wired by SPI to the Arduino Nano.

## Pinout used by this project

| ADS1292R signal | Arduino Nano pin |
|------------------|-------------------|
| PWDN / RESET     | D4                |
| START            | D5                |
| DRDY             | D6                |
| CS               | D7                |
| DIN / MOSI       | D11               |
| DOUT / MISO      | D12               |
| SCLK             | D13               |
| GND              | GND               |

D11/D12/D13 are the ATmega328P's hardware SPI MOSI/MISO/SCK pins. This mapping is
**confirmed working** on real hardware — a bare Nano and a separate Uno, each
wired directly to the module with jumper wires (bypassing the CWXS carrier PCB
entirely, whose own internal routing between its Nano socket and this module is
still unverified). Getting a real `ADS1292R detected` result also required
slowing the SPI clock to 500 kHz (the datasheet's ~4 MHz max is too fast for
jumper wires — it silently read back an all-zero ID register instead of an
error) — see `firmware/cwxs_ads1292r_nano/README.md` for the full story.

## Register map

Register addresses and SPI command op-codes come directly from the public TI
ADS1292R datasheet and are implemented in
`firmware/cwxs_ads1292r_nano/ads1292r_registers.h`:

| Register    | Address |
|-------------|---------|
| ID          | 0x00    |
| CONFIG1     | 0x01    |
| CONFIG2     | 0x02    |
| LOFF        | 0x03    |
| CH1SET      | 0x04    |
| CH2SET      | 0x05    |
| RLD_SENS    | 0x06    |
| LOFF_SENS   | 0x07    |
| LOFF_STAT   | 0x08    |
| RESP1       | 0x09    |
| RESP2       | 0x0A    |
| GPIO        | 0x0B    |

## Driver functions

Implemented in `firmware/cwxs_ads1292r_nano/ads1292r.{h,cpp}`:

- `readRegister(address)` / `writeRegister(address, value)`
- `sendCommand(command)`
- `startConversions()` / `stopConversions()`
- `readData(ch1, ch2, status)`
- `resetDevice()`
- `verifyDevice()` — reads the ID register and checks it against the known
  ADS129x family bit pattern, used for the startup "ADS1292R detected /
  NOT FOUND" diagnostic.

## ADC counts to volts

The ADS1292R reports each channel as a 24-bit two's-complement code. Per the
datasheet, for a fully differential input:

```
code = 2^23 * gain * Vin / Vref
Vin  = code * Vref / (2^23 * gain)
```

Implemented in `src/signal_processing/units.py::adc_counts_to_volts`. This
conversion is only correct if `vref_volts` and `pga_gain` match the ADS1292R's
actual register configuration — both are read from Settings
(`ADS1292RConfig`), never hard-coded as assumed facts.

## Unverified defaults

The application's default `ADS1292RConfig` (`src/config.py`) uses the ADS1292R
**power-on-reset** defaults — internal 2.42 V reference, PGA gain of 6 — purely so
unit conversion has a sane starting point. These are documented chip defaults, not
a measurement of what the CWXS stock firmware actually configures at runtime.
`TO BE VERIFIED ON HARDWARE` before trusting converted µV/mV values from a CWXS
unit running its original firmware.

Also unverified:

- which physical channel (1 or 2) is wired to the ECG electrodes vs. the
  respiration path on this specific module/PCB revision;
- the exact 24-bit sample framing/byte order used by the stock CWXS firmware
  (this project's own `src/acquisition/protocol.py` binary frame is a distinct,
  self-designed format for the alternative firmware only).
